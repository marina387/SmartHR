# SmartHR — дипломный проект

Этот проект объединяет две простые демонстрационные части:
- веб-оценку кандидатов по вакансиям;
- компактный RAG-демо для обучения на небольшом наборе HR-документов.

## Что реализовано

- Flask-приложение с REST API для оценки кандидатов;
- простой скрейпер/парсер для текста резюме и вакансий;
- scoring через обученную базовую модель `models/matching_model.pkl`;
- индивидуальные веса критериев для каждой вакансии;
- реляционная SQLite-база через SQLAlchemy;
- история оценок, этапов, интервью, обратной связи и переносов;
- серверный API чат-ассистента с инструментами доступа к SmartHR;
- подтверждаемые через HR действия чата: этап, перенос и архивирование;
- история диалогов, действий, источников и обратной связи HR;
- независимый адаптер чат-модели и подготовленный контракт её артефакта;
- семантический RAG на sentence-transformers и FAISS с резервным TF-IDF-поиском;
- минимальный набор HR-документов для демонстрации.

## Запуск веб-части

```bash
pip install -r requirements.txt
python -m flask --app app db upgrade
python app.py
```

Откройте браузер по адресу http://localhost:5000

Рабочие данные находятся в `data/smarthr.db`. JSON-файлы больше не используются
приложением как хранилище. Для однократного импорта старых данных выполните:

```bash
python scripts/migrate_json_to_sqlite.py
```

Перед импортом скрипт создаёт резервную копию JSON в `data/json_backup`.

## Проверка качества модели

```bash
python evaluation/evaluate_model.py
```

Скрипт не переобучает модель. Он восстанавливает тестовую часть исходного датасета,
рассчитывает метрики и сохраняет таблицы, графики и отчёт в `evaluation/results`.

## Как рассчитывается оценка

Текст резюме преобразуется в структурированный профиль и одиннадцать признаков,
описанных в `models/model_metadata.json`. Модель возвращает вероятность
соответствия кандидата вакансии. Эта вероятность используется для оценки
профессионального соответствия, после чего оценки критериев объединяются с
индивидуальными весами вакансии. Вместе с результатом сохраняются признаки,
версия модели, веса и объяснения.

### Объяснения оценки

При срабатывании обязательного фильтра карточка показывает неподтверждённые
требования и «Не оценивалось» вместо нулей по всем критериям. Рассчитанные
баллы сопровождаются комментариями и вкладом в итог; причина архивирования
показывается отдельно. [Формат объяснений и история](docs/score_explanations.md).

## Подготовка чат-модели

Пока обученная модель отсутствует, `/api/chat` использует детерминированный
`MockChatModel` и показывает только сведения, подтверждённые базой и документами.
Совместимая локальная модель автоматически загружается из `models/chat_model`.
Требования к артефакту, API и сценариям описаны в `docs/chat_requirements.md`.
Полная процедура подготовки, обучения, оценки и установки описана в
`docs/chat_training.md`.

Зависимости запуска модели и её обучения разделены:

```bash
pip install -r requirements-chat.txt
pip install -r requirements-training.txt
```

Основные команды команды обучения:

```bash
python scripts/train_chat_model.py --config configs/chat_training.yaml --check
python scripts/train_chat_model.py --config configs/chat_training.yaml
python scripts/evaluate_chat_model.py --model models/chat_model_candidate
python scripts/install_chat_model.py models/chat_model_candidate --smoke-test
```

## Структура

- app.py — Flask-точка входа;
- src/models.py — реляционная схема SQLAlchemy;
- src/storage/sql_storage.py — репозитории SQLite;
- migrations — версии структуры базы данных;
- src/services — логика оценки и парсинга;
- src/core — минимальный RAG-пайплайн;
- src/chat — API-независимые адаптеры модели, инструменты и оркестрация чата;
- src/cli — CLI-демо;
- tests — базовые проверки.

## Проверки приложения

Установка: `python -m pip install -r requirements-test.txt`.
Единый запуск: `python run_checks.py` (в Windows — `.venv-run\Scripts\python.exe run_checks.py`).
Проверяются Python, JavaScript, зависимости и тесты приложения на отдельной базе.
Обучение не запускается. [Состав проверок и изоляция данных](docs/testing.md).

## Запуск в Windows

Откройте `start_smarthr.bat`. При первом запуске создаётся `.venv-run` и устанавливаются зависимости исполнения; обучение не запускается. Затем откройте http://localhost:5000 . Для остановки нажмите Ctrl+C в окне сервера.

Проверка окружения без запуска: `.venv-run\Scripts\python.exe run_smarthr.py --check`.
Перед миграциями сохраняется полный комплект базы и загруженных документов в `data/backups`.
Для отдельной копии остановите сервер и выполните `.venv-run\Scripts\python.exe run_smarthr.py --backup-only`.
Восстановление выполняется в новую папку, без перезаписи рабочих данных.
Диагностика: `python run_smarthr.py --diagnose`; состояние базы: `/api/health`.
[Команды проверки, восстановления и описание журнала](docs/backup_diagnostics.md).

## Работа с документами и чатом

В разделе «Документы» доступны загрузка PDF/DOCX/TXT/MD (до 16 МБ), чтение извлечённого текста, скачивание оригинала и переход к вопросу в чате. Новые документы сразу доступны поиску и сохраняются после перезапуска. Сканированные PDF без текстового слоя требуют предварительного распознавания.

Чат запоминает выбранного кандидата внутри диалога. Укажите другую фамилию или ID для переключения; «Новый диалог» сбрасывает текущий контекст, сохраняя старую переписку в базе. Операции изменения данных выполняются только после подтверждения.

Интервью одного кандидата не могут пересекаться; другие пересечения календаря и назначение в прошлом сопровождаются предупреждением. После отмены последнего интервью кандидат возвращается в работу HR, если он ещё не на более позднем этапе.

### Управление библиотекой документов

Откройте документ и раздел «Управление документом», чтобы изменить название, загрузить новую версию или удалить документ из каталога. Для удаления необходимо отметить подтверждение. Новая версия может быть в другом поддерживаемом формате; ссылка и название документа сохраняются. После операции каталог и поисковый индекс обновляются автоматически.

Изменения сохраняются в `data/documents/library.json`, исходные названия загруженных файлов — в сопутствующих JSON. Удаление исключает документ из каталога и поиска, сохраняя исходники и прежние версии на диске. Для резервного копирования библиотеки сохраняйте всю папку `data/documents`. История старых ответов чата не переписывается.

### История диалогов

В чате справа отображаются сохранённые разговоры с названием по первому вопросу, датой последнего сообщения и кандидатом. «Показать ещё» открывает следующие записи. На узком экране список доступен по кнопке «Диалоги». Выбор разговора восстанавливает переписку, источники, оценки ответов, действия и контекст кандидата/вакансии. После нового сообщения диалог поднимается в начало списка. «Новый диалог» начинает пустую переписку и сохраняет старую в базе; новая запись создаётся при отправке первого сообщения. Ссылку с `conversation_id` можно открыть повторно на этой же установке приложения.

## Состав опубликованного проекта

В репозиторий включены исходники, тесты, миграции и небольшая модель оценки `models/matching_model.pkl` с метаданными. Рабочая база, резюме, датасеты, загруженные документы, логи и большие веса чат-модели не публикуются. При первом запуске база создаётся миграциями. Без локального артефакта чат-модели используется предусмотренный проектом `MockChatModel`. Известные ограничения описаны в `docs/project_readiness_review.md`.
