# Проверка приложения одной командой

Установите зависимости запуска и тестов в отдельное окружение:

```powershell
python -m pip install -r requirements-test.txt
python run_checks.py
```

В локальном Windows-окружении проекта:

```powershell
.\.venv-run\Scripts\python.exe run_checks.py
```

Команда завершается ненулевым кодом при ошибке. Она проверяет синтаксис
Python-кода приложения и миграций, JavaScript через `node --check`,
согласованность установленных зависимостей через `pip check`, затем запускает
весь набор тестов приложения. Node.js должен быть доступен в PATH.
Если нужен только Python-набор, отсутствие проверки JavaScript нужно указать
явно: `python run_checks.py --skip-javascript`. Это не полный запуск.

JUnit XML сохраняется в отдельной папке `data/test-runs/check-*/results.xml`;
путь выводится при запуске. Временные данные не публикуются в Git.

## Обычный pytest

```powershell
python -m pytest
python -m pytest tests/test_system_scenarios.py -q
```

`pytest.ini` ограничивает стандартный сбор папкой `tests`. Старый корневой
`test_api.py` и ручной `scripts/test_chat.py` не импортируются и не обращаются
к работающему серверу. Для просмотра состава: `python -m pytest --collect-only -q`.

## Изоляция

До импорта приложения `tests/conftest.py` задаёт отдельную SQLite в
`data/test-runs/application-*`, заменяя даже ранее заданный SMARTHR_DATABASE.
Миграции применяются к новой тестовой базе. Рабочая база не копируется
и не используется как тестовая. Проверяются текущая версия миграций,
внешние ключи, целостность и открытие основных страниц и API.

Загрузки документов направляются во временную папку. Чат использует MockChatModel,
обычный поиск — TF-IDF, скачивание моделей отключено. При этом тесты оценки
используют существующий scoring-артефакт и проверяют реальное предсказание;
переобучение, изменение признаков или весов не выполняются. Это не проверка
качества генерации тяжёлой чат-модели и не нагрузочное тестирование.

На Windows отключается только необязательная служебная ссылка pytest
`*current` для временных каталогов: в ограниченном окружении её создание
может зависать. Сам pytest, его временные каталоги, проверки и код приложения
работают обычным образом. Поддерживаемая версия pytest указана в requirements-test.txt.

После завершения переменные окружения восстанавливаются. Временные данные
остаются для диагностики в игнорируемой папке; это только тестовые данные.

## Отдельные проверки инструментов обучения

По умолчанию до импорта исключены пять модулей:

- test_chat_training.py;
- test_chat_dataset.py;
- test_real_dataset_collection.py;
- test_synthetic_chat_dataset.py;
- test_rag_chat_dataset.py.

Их зависимости и подготовка данных не нужны для обычного запуска тестов.
Они не изменялись и в этом этапе не запускались. При отдельной работе с
инструментами можно установить requirements-training.txt и явно выбрать:

```powershell
python -m pytest --training-tools -m training_tools
```

Флаг разрешает сбор проверок утилит, а не запускает обучение модели.
В итогах обычного запуска явно указано, что эти модули не проверялись.

## Исправленные проверки

Устаревший тест модели больше не требует удалённых признаков salary_ratio
и exp_within_range. Он проверяет рублёвые значения зарплат, опыт, образование
и соответствие порядка столбцов текущим метаданным артефакта. Код модели,
метаданные и веса не изменены.

Полный прогон также выявил блокировку временного документа в Windows при
откате неуспешной индексации. Удаление повторяется кратко только при кодах
блокировки 32/33; остальные ошибки не скрываются. Добавлена регрессия,
подтверждающая сохранение старого документа и индекса.

приложения, синтаксис 57 Python-файлов и 10 JavaScript-файлов, `pip check`.
Пять модулей утилит обучения и подготовки данных не запускались.
Контрольные суммы рабочей базы, scoring-артефакта и его метаданных до и
после проверки совпали; внешние ключи рабочей базы — 0 нарушений.
