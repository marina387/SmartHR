# Проверка входных данных и ошибки API

Обучение, датасеты, признаки и веса моделей не изменяются. Миграция базы
для этого этапа не требуется.

## Формат запросов

До вызова сервисов API проверяет, что JSON корректен и содержит объект.
Массив, число, строка, boolean и null не заменяются молча пустым объектом.
Неверные типы строковых полей, списков требований, весов, оценок, флагов,
истории чата и числовых значений возвращают 400. Проверяются конечность
чисел, диапазоны, целая длительность от 1 до 1440 минут и корректность
календарных дат и времени (`YYYY-MM-DD`, `HH:MM`). Диапазоны вакансии
проверяются также после объединения частичного обновления с текущей записью.
Неизвестные дополнительные поля пока не запрещены для совместимости.

Загрузка файлов и симуляция продолжают принимать формы; остальные запросы
с телом должны использовать `application/json`. Симуляция из формы
учитывает выбранную вакансию. Если ID не задан, используется VAC_001;
она должна существовать, и её обязательные требования применяются.

## Ответы

- 400: некорректные данные или повреждённый/неподдерживаемый файл;
- 404: отсутствующая запись или неизвестный адрес API;
- 405: неподдерживаемый HTTP-метод;
- 409: попытка удалить вакансию, на которую ссылаются рабочие записи;
- 413: превышен предел запроса 16 МБ;
- 415: неподходящий Content-Type;
- 502/504: ошибка доступа к hh.ru / тайм-аут;
- 500: непредвиденная ошибка без внутренних путей и текста исключения в ответе.

Ошибки API имеют JSON-формат с полем `error`. Для обычных HTML-страниц
сохраняется HTML-ответ. Ошибка не заменяет успешный результат. Транзакции
предыдущего этапа продолжают откатывать связанные изменения при сбое.

Отсутствующие кандидаты, вакансии и шаблоны проверяются до записи там,
где раньше могли приводить к ошибке внешнего ключа или тихому пропуску ссылки.
Наличие кандидата/вакансии проверяется даже для нового отменённого интервью.

## Файлы и импорт HH

API резюме поддерживает TXT в UTF-8 (включая BOM), PDF и DOCX. Старый DOC
не принимается как DOCX. Файл с повреждённой структурой или неверной
кодировкой возвращает понятную ошибку 400.

Импорт допускает прямые HTTPS-ссылки на резюме только на `hh.ru` и `www.hh.ru`,
без логина/пароля, фрагмента и нестандартного порта. Адреса вида
`127.0.0.1/?source=hh.ru`, `hh.ru.evil.example` и другие обходы подстрокой
отклоняются до сетевого запроса. Региональные домены пока не включены:
нужно скопировать прямую ссылку с разрешённого домена.

Автоматические перенаправления отключены. При редиректе приложение просит
прямую ссылку вместо перехода по Location. Установлены тайм-ауты соединения
и чтения; страница читается потоком с пределом 2 МБ. Ответ закрывается
как при успехе, так и при ошибке. Контроль входа в аккаунт HH и обход
ограничений доступа HH не добавлялись.

## Проверки

Регрессии включают ошибочные тела и типы полей на API-маршрутах,
отсутствующие записи, ограничения запросов, испорченные файлы, конфликты
удаления и отсутствие внутренних деталей в ошибках. Проверяется, что
ошибочные запросы не меняют базу. Сетевые сценарии HH проверяются на
подставных ответах; тесты не обращаются к реальным резюме и внутренним адресам.

На текущем Windows-окружении pytest иногда зависает при создании своей
необязательной временной символической ссылки. Для локальной проверки
используется временный runner, отключающий только эту служебную ссылку;
тестовые проверки и код приложения не подменяются.

25 октября 2026: 245 тестов перечисленных сценариев и регрессий предыдущих
этапов прошли успешно. Рабочая база не изменялась; проверка внешних ключей
возвращает 0 нарушений.
