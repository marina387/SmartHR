# Чат-ассистент SmartHR: требования и контракт

## Назначение

Чат помогает HR получать объяснения на основе сохранённых данных SmartHR и HR-документов. Модель не является источником оценок, этапов и решений: такие сведения передаются ей из базы данных.

## Поддерживаемые сценарии

1. Сведения о выбранном кандидате и вакансии.
2. Объяснение последней оценки и критических несоответствий.
3. Текущий этап, история этапов и интервью.
4. Поиск ответа в HR-документах с указанием источников.
5. Подготовка вопросов для интервью и черновиков сообщений.
6. В дальнейшем — предложение альтернативной вакансии.

Изменяющие данные операции выполняются только отдельным подтверждённым HTTP-запросом. Ответ чата сам по себе ничего не меняет.

Реализованные сценарии:

- подробное объяснение сохранённой оценки по критериям и весам;
- поиск альтернативных вакансий действующим сервисом SmartHR;
- формирование вопросов для интервью из контекста кандидата и вакансии;
- черновик приглашения или корректного отказа;
- предложение смены этапа, переноса или архивирования.

Для изменяющей операции сервер возвращает подписанный одноразовый контекст
подтверждения. Интерфейс показывает отдельную кнопку, запрашивает подтверждение HR и
только после этого отправляет `POST /api/chat/actions/confirm`. Подпись действует 15
минут. Перед переносом и архивированием бизнес-условия проверяются повторно, поэтому
устаревшая рекомендация не применяется.
Для подписания подтверждений задаётся уникальный `SMARTHR_SECRET_KEY`; пример всех
переменных находится в `.env.example`.

## История и обратная связь

Диалоги сохраняются в таблицах `chat_conversations`, `chat_messages`, `chat_actions`
и `chat_response_feedback`. Для ответа фиксируются модель, источники и поисковый
backend. После обновления страницы текущий диалог восстанавливается через
`GET /api/chat/conversations/{id}`.

HR может отметить ответ как полезный, бесполезный, содержащий фактическую ошибку или
неверный источник. Для фактической ошибки можно сохранить исправленный ответ и явно
подтвердить его использование при подготовке обучающего датасета. Неисправленные и
неподтверждённые ответы автоматически обучающими примерами не считаются.

## API

`POST /api/chat`

```json
{
  "message": "Почему кандидат не рекомендован?",
  "conversation_id": null,
  "candidate_id": "CV_001",
  "vacancy_id": "VAC_001",
  "history": []
}
```

Ответ содержит `answer`, `sources`, `suggested_action`, `model` и `conversation_id`.

Подтверждение действия:

```json
POST /api/chat/actions/confirm
{
  "confirmation_token": "подписанный токен из suggested_action",
  "hr_id": "HR_001"
}
```

## RAG и документы

Поддерживаются TXT, Markdown, PDF и DOCX. Для каждого документа сохраняются название,
тип, исходное имя, размер и время изменения. Основной режим поиска — мультиязычные
эмбеддинги `sentence-transformers` и индекс FAISS. Если зависимости или модель
недоступны, приложение автоматически переключается на TF-IDF и продолжает работать.

Переменные окружения:

```text
RAG_BACKEND=auto
RAG_EMBEDDING_MODEL=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
RAG_ALLOW_MODEL_DOWNLOAD=0
```

Значение `RAG_BACKEND=tfidf` принудительно включает резервный поиск. Источник каждого
результата содержит идентификатор документа, имя файла, тип, номер фрагмента и оценку
релевантности. `RagPipeline.upsert_document()` обновляет документ с перестроением
индекса, а `RagPipeline.delete_document()` удаляет его только из поискового индекса.
Для первой загрузки модели можно временно установить `RAG_ALLOW_MODEL_DOWNLOAD=1`.
В штатном запуске сетевые обращения отключены, а при отсутствии локального кэша
автоматически используется TF-IDF.

## Контракт модели

По умолчанию приложение ищет модель в `models/chat_model`. Обязателен файл `smarthr_model_metadata.json`:

```json
{
  "model_type": "causal_lm",
  "base_model": "название исходной модели",
  "format_version": "1.0",
  "language": ["ru"],
  "context_length": 4096,
  "supports_tools": false,
  "training_dataset_version": "1.0"
}
```

Путь можно изменить переменной `CHAT_MODEL_PATH`. Пока артефакта нет, используется `MockChatModel`, возвращающий только подтверждённый контекст. После появления совместимой модели код API и интерфейса изменять не требуется.
