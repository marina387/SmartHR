# Редактирование кандидата и повторная оценка

В существующей форме «Редактировать» доступны имя, почта, телефон, заметки HR и текст резюме. «Сохранить и переоценить» выполняет расчёт по текущей вакансии её действующими весами и обязательными требованиями. Изменение текста без переоценки отклоняется API, чтобы не показывать старый результат для нового резюме.

Предыдущие текст и результат сохраняются в `resume_revisions` и доступны в карточке. Новый результат записывается в историю оценок. Сохранение атомарно: ошибка расчёта или записи отменяет операцию. Этап рассмотрения, решение HR в связях кандидата с вакансией и состояние архива автоматически не меняются.

Чат поддерживает точное совпадение коротких фамилий и уточняет неоднозначность. Совпадающие должность и название вакансии выводятся в контексте один раз. PDF читаются через `pypdf`; миграции используют актуальное свойство SQLAlchemy `engine`.

## Проверка этапа

2026-10-26: `python run_checks.py` — 318 тестов, без предупреждений; синтаксис 61 Python-файла и 10 JavaScript-файлов, зависимости без конфликтов. Проверки включают повторную оценку, сохранение предыдущего результата, откат при ошибке, короткие фамилии и чтение настоящего PDF обоими загрузчиками. Обучающие утилиты исключены из стандартного набора.

Рабочие базы, резюме, резервные копии, отчёты тестов и одноразовые операции с проверочными данными не публикуются. Веса модели и обучение не изменялись. Этот этап не добавляет интерфейс произвольного переноса на нерекомендованную вакансию.

## Порядок веток

Ветки последовательные: каждая следующая включает предыдущую. При поэтапном ревью сравнивайте её с предыдущим этапом:

1. `main` → `feature/database-integrity`
2. `feature/database-integrity` → `feature/operation-transactions`
3. `feature/operation-transactions` → `feature/recruitment-rules`
4. `feature/recruitment-rules` → `feature/input-validation`
5. `feature/input-validation` → `feature/application-checks`
6. `feature/application-checks` → `feature/backup-diagnostics`
7. `feature/backup-diagnostics` → `feature/score-explanations`
8. `feature/score-explanations` → `feature/candidate-reassessment`

При сохранении этой цепочки объединяйте этапы в `main` по порядку обычным merge с сохранением истории. Squash/rebase потребует пересборки зависимых веток. На момент публикации этого этапа слияние в `main` не выполнялось.
