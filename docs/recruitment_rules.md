# Согласованные правила подбора

Обучающие скрипты, датасеты, веса и признаки моделей не меняются.
Меняется применение правил вокруг существующей оценки.

## Обязательные требования

`CandidateScoringService` всегда объединяет обязательные требования вакансии
с дополнительными требованиями запроса. Отсутствующее поле, пустой список
или более короткий список запроса не отключают требования вакансии.
Строки с переносами нормализуются в список; дубликаты без учёта регистра
проверяются один раз. Это общий путь для API оценки, ручного создания,
демонстрационного кандидата, архивирования и поиска альтернатив.

Проверка самих требований и ML-прогноз не изменены. Если ранее API пропускал
требование вакансии, результат теперь может отличаться: при неподтверждённом
обязательном требовании возвращается отказ и список требований.

## Этапы и пересчёт

Повторная оценка обновляет численные показатели. Она не возвращает кандидата
в `new` и не отменяет решения HR, интервью, оффер, найм или закрытие рассмотрения.
Для первоначальной оценки и этапов `new/scored/recommended` действует обычный
выбор по баллам; критический фильтр имеет приоритет перед высоким баллом.

Из закрытого рассмотрения или найма нельзя перейти прямо на активный этап
в обход возвращения в работу. HR сначала явно выбирает `in_review`.
Общее правило сервиса действует и при подтверждении действия чата.
Переход `offer → hired` по-прежнему разрешён. Полная новая матрица всех
переходов и обязательная последовательность всех промежуточных этапов
не вводятся.

## Интервью

Для нового неотменённого интервью нужны существующие активные кандидат
и вакансия. При закрытом рассмотрении, оффере или найме сначала требуется
явно вернуть кандидата в работу. Для архивного кандидата также необходимо
восстановить его карточку. Эта проверка применяется при создании,
возобновлении и изменении расписания запланированного интервью.

Отмена и редактирование исторических заметок остаются доступны и не
возобновляют рассмотрение. Существующие интервью автоматически не удаляются.
Этап «интервью» сам по себе не создаёт встречу в календаре.

## Альтернативные вакансии

Все активные этапы воронки учитываются при исключении уже связанных вакансий
из рекомендаций. Закрытая связь может рассматриваться повторно;
добавление и перенос используют тот же список закрытых статусов.

## Проверка

Тесты используют отдельные данные. Проверяются невозможность отключить
требования вакансии во всех трёх входных сценариях, закрытые этапы и явный
возврат в работу, архивные/отсутствующие записи, обход через чат и изменение
календаря, сохранение HR-этапа при пересчёте, исключение активных связей
из альтернатив и регрессии транзакций предыдущего этапа.

Миграция и изменение существующих рабочих записей не требуются.
